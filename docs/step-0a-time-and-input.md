## 1. Что было (`timing=legacy`)

```js
loop(){ requestAnimationFrame(loop);          // timestamp из rAF ИГНОРИРУЕТСЯ
  tgt = slowmo>0 ? (slowmo--, 0.4) : 1;       // slowmo — счётчик КАДРОВ
  slowTS += (tgt - slowTS)*0.18;              // сглаживание с постоянной «за кадр»
  physAcc += slowTS;                          // +1.0 за КАДР: slowTS безразмерен
  if(physAcc>3) physAcc=3;
  while(physAcc>=1 && st<4){ update(); physAcc-=1; }
  slowLerp = slowTS>0.985 ? 1 : physAcc;      // интерполяция ТОЛЬКО в слоумо
}
```

`physAcc` — не аккумулятор времени, а счётчик кадров. `SIM_DT=1/60` в цикл не входит вообще:
он используется только внутри `update()` как приращение `_simT`, и ещё `_vsTime += 1/60` и `t++`.
`performance.now()` в цикле отсутствует (реальные часы были только у рига — отсюда двое часов
в одном кадре, дефект §6.10 аудита).

`[ВЫВОД]` Один кадр = один `update()` = `+1/60` к `_simT`. Значит `_simT` идёт со скоростью
`refreshRate/60` от реального времени. При 45 Гц это 0.75 — совпадает с измеренными аудитом 0.757.

## 2. Что стало (`timing=fixed`)

```
realDt = (nowMs - prevNowMs)/1000                    // nowMs — аргумент rAF, monotonic
realDt = clamp(realDt, 0, TM_MAX_FRAME_DT)           // 0.25 с
slowTS += (target - slowTS) * (1 - exp(-11.9074*realDt))
slowmo -= realDt*60                                  // длительность в реальных секундах
accumulator += realDt * slowTS
while (accumulator >= SIM_DT && steps < TM_MAX_STEPS) {   // 5
    applyPendingInput(); update(); accumulator -= SIM_DT
}
if (accumulator >= SIM_DT) { droppedRealTime += accumulator; accumulator = 0 }
renderAlpha = accumulator / SIM_DT   →   slowLerp
```

| Константа | Значение | Зачем |
|---|---|---|
| `SIM_DT` | 1/60 с | не менялась |
| `TM_MAX_FRAME_DT` | 0.25 с | кадр длиннее — это провал (таб/звонок), а не медленный кадр |
| `TM_MAX_STEPS` | 5 | потолок catch-up за кадр = 83 мс симуляции; анти-спираль |
| `TM_LONG_FRAME` | 0.05 с | порог регистрации «длинного кадра» |
| `TM_SLOW_RATE` | 11.9074 | `1-exp(-RATE/60)=0.18` → при 60 FPS в точности прежнее сглаживание |

Ключевые свойства:

- **`_simT` растёт только внутри `update()` на `SIM_DT`** — как и раньше.
- **Число `update()` задаёт реальное время**, а не частота дисплея.
- **Рендер интерполирует** `prev→cur` по `alpha` каждый кадр (в legacy — только в слоумо).
- **Ресинк** на `visibilitychange`, `pageshow` и при любом уходе с экрана `play`:
  следующий кадр берёт `dt=0` и пустой аккумулятор → возврат из фона не даёт ни catch-up,
  ни импульса вращения.
- **`vsRestore()` обнуляет и новый аккумулятор** — недобранный шаг не протекает в следующую
  попытку с чекпоинта.
- **Отброшенное время учитывается честно** — `droppedRealTime`, а не молча теряется.
- `Date.now()` не используется нигде в кадровой физике; только `performance.now()` / rAF-timestamp.

**Тело кадра вынесено в `_tmFrameBody(nowMs)`.** `loop()` = rAF-перезапрос + `try/catch` + вызов
этого тела. Тестовая оснастка гоняет **именно `_tmFrameBody`**, а не свою копию логики, — иначе
тест проверял бы сам себя.

### Слоумо и хитстоп

`[ИЗМ]` Длительность в **реальных** миллисекундах (замер через явный аксессор `__tmSlowmo` /
`__tmHitstop`; `eval('slowmo')` из инжектированного скрипта не видит лексику `<script>` и мерил бы
пустую глобальную переменную — первая версия замера была именно такой и была выброшена):

| | 30 FPS | 60 FPS | 120 FPS |
|---|---|---|---|
| `slowmo=30`, legacy | 1000 мс | 500 мс | 250 мс |
| `slowmo=30`, **fixed** | 567 мс | 517 мс | 517 мс |
| `hitstop=6`, legacy | 200 мс | 100 мс | 50 мс |
| `hitstop=6`, **fixed** | 133 мс | 117 мс | 108 мс |

`[ВЫВОД]` В legacy обе длительности имеют разброс 4× по частоте кадров. В fixed слоумо
привязано к реальным секундам (остаток — гранулярность одного кадра детекции), хитстоп —
ровно 6 шагов симуляции = 100 мс sim-времени при любом FPS.

**Отличие от legacy, названное явно:** в legacy при 60 FPS `slowmo=30` длится 500 мс, в fixed —
517 мс. Расхождение 17 мс = один кадр: цикл выходит на том кадре, где счётчик пересёк ноль.
Это не подкрутка, а квантование; legacy-режим сохраняет прежнее поведение без изменений.

| Вызов | Что делает |
|---|---|

| `__timeReset()` | обнулить счётчики |
| `__timeResync()` | ресинк временной базы вручную |

| Вызов | Что делает |
|---|---|
| `__inputTraceStart()` / `__inputTraceStop()` | запись |
| `__inputTraceGet()` | `{meta, timeReport, raw[], resolved[]}` |
| `__inputTraceCounts()` | `{status, raw, resolved, ms}` |
| `__inputTraceLast()` | последний сохранённый в `localStorage` |
| `__inputTraceValidate(tr?)` | поиск дефектов трейса (§9, NC2) |
| `__inputTraceLoad(json)` | загрузить для реплея |
| `__inputTraceReplay({fps, seconds, mode, jitter, gapAtMs, gapMs, sampleEvery})` | разомкнутый реплей |
| `__inputTraceReport(tr?)` | то же, что `Validate` |
| `__timingTest({seconds, trace, sampleEvery})` | автотест 30/45/60/120 + jitter + gap |
| `__timingNegativeControls({seconds, trace})` | три негативных контроля |
| `__tmCompare(a,b)` | сравнение двух прогонов по тикам |

**Скриптовый пилот (`__vsRun` / `__vsRecord`) не тронут и не смешан с человеческим трейсом.**
Он остаётся исключительно инструментом регрессии (правило 13). Реплей человеческого трейса
разомкнутый: подаёт записанные действия по их времени и **не читает состояние байка**.

## 5. Состав `__timeReport()`

`timingMode`, `realElapsed`, `simElapsed`, `simToRealRatio`, `renderFrames`, `physicsSteps`,
`renderFPS`, `physicsHz`, `frameDt{min,median,p95,max,n}`, `stepsPerFrame{...}`, `accumulator`,
`maxAccumulator`, `maxAccumulatorPostDrain`, `maxAccPostRaw`, `clampedFrameCount`,
`droppedRealTime`, `visibilityResetCount`, `longFrameCount`, `slowTS`, `slowmo`, `renderAlpha`,
`viewportCssW/H`, `canvasBackingW/H`, `devicePixelRatio`, `effectiveDPR`, `userAgent`,
`currentScreen`, `currentLevel`, `controlScheme`, `build`, `simDt`.

Все поля — счётчики измерений. Ни одно не является константой, сравниваемой сама с собой
(урок `__vsDebugStats`, §7.3 аудита). Способность каждого гейта провалиться доказана
негативными контролями (§9).

`[ИЗМ]` Счётчики растут **только в точке вызова `update()` из цикла**, поэтому скриптовые
прогоны их не загрязняют: после `__vsRun('gas', 2600)` отчёт показывает `physicsSteps = 0`.

## 6. Схема трейса

```jsonc
{
  "meta": {
    "formatVersion": 1, "build": "...", "commit": "...", "timingMode": "fixed", "simDt": 0.016666,
    "viewportCss": [430,932], "canvasBacking": [860,1582], "canvasRect": [l,t,w,h],
    "devicePixelRatio": 3, "effectiveDPR": 2, "device": "<userAgent>", "orientation": "portrait-primary",
    "level": "vertical-slice", "query": "?...", "ctrlScheme": "btn4", "pumpSide": "left",
    "recordedAt": "ISO", "stoppedAt": "ISO", "durationRealMs": 12345,
    "initial": { "x":…, "y":…, "ang":…, "vx":…, "vy":…, "simT":…, "vsCP":…, "screen":"play" }
  },
  "timeReport": { /* §5 на момент остановки */ },
  "raw":      [ {"k":"start|move|end|cancel","id":1,"rt":123.4,"st":2.05,
                 "cx":..,"cy":..,"kx":..,"ky":..,"z":"gas","n":2,"sc":"play",
                 "r":[l,t,w,h],"or":"portrait-primary"} ],
  "resolved": [ {"rt":123.4,"st":2.05,"f":123,"d":true,"b":false,"lx":-1,
                 "jr":0,"bo":0,"tk":0,"th":false,"ci":null,"cs":"btn4",
                 "at":{"1":"gas"},"why":"touchstart"} ]
}
```

- `rt` — монотонные миллисекунды от начала записи; `st` — `_simT`; `f` — индекс `update()`.
- `z` в `raw` на `touchmove` считается **чистым** hit-тестом `_itHitZone` — `pointerDown()`
  повторно не вызывается, у него побочные эффекты (пауза, PUMP, прыжок).
- `resolved` пишется дельтой: запись появляется только при изменении набора действий.
- `why` — причина: `touchstart` / `touchmove` / `touchend` / `touchcancel` / `keydown` / `keyup` /
  `mousedown` / `mouseup` / `step` (изменение не от DOM: автогаз `btn2`, распад `jumpReq`) /
  `visibility:hidden` / `record:start`.

**Приватность.** Пишутся только координаты касаний внутри канваса и состояние игровых действий.
Текст клавиш, содержимое `localStorage`, cookies и любые персональные данные не записываются.

## 7. Как записать трейс на телефоне (без DevTools)

**Ссылка для ручного теста:**

```
https://cryptomafioznik.github.io/cryptobill/toys/chartrider.html?render=game&camera=side&rig=cutout&rider=hybrid&level=vertical-slice&timing=fixed&inputTrace=1&cb=0a16
```

Порядок:

1. Открыть ссылку в Safari, **portrait**.
2. Вверху, в пустом небе, появится панель со статусом и тремя кнопками.
3. Нажать **● ЗАПИСЬ** — статус станет `RECORDING`, счётчики `raw` / `res` пойдут вверх.
4. Играть **10–15 секунд** обычным образом. Одновременно записывать экран (Screen Recording).
5. Нажать **■ СТОП**.
6. Нажать **⬇ JSON** — файл `trace-0a-<дата>.json` уйдёт в Загрузки.
   Если скачивание не сработает — **⧉ КОПИЯ**: JSON уйдёт в буфер обмена, а при отказе
   буфера появится текстовое поле с уже выделенным текстом.
7. Прислать **оба** файла: JSON и видео.

Панель:
- статус `RECORDING` / `STOPPED` / `EXPORTED`, число raw-событий и resolved-изменений, секунды;
- вторая строка — режим времени, `simToRealRatio`, реальный FPS, число физ-шагов;
- `[ИЗМ]` геометрия: панель `top 96 … bottom 177` CSS-px. Блок кнопок начинается на `H-246`:
  686 на 430×932 и 322 на SE 320×568 — перекрытия нет ни там, ни там (проверено скриншотами).
- трейс переживает экран смерти: при гибели делается снимок в `localStorage`
  (`__inputTraceLast()` достаёт его после перезагрузки).

Консоль Safari не нужна ни на одном шаге.

## 8. Результаты 30 / 45 / 60 / 120

`[ИЗМ]` Синтетические расписания через **production-код кадра**. Трасса `vertical-slice`,
сценарий «зажатый газ» 20 с, сравнение **по каждому из 767 тиков** (`sampleEvery=1`),
портрет 430×932.

| Расписание | physicsSteps | simToRealRatio | contact events | Исход | Побитово vs 60 |
|---|---|---|---|---|---|
| 30 FPS | 768 | 1.000 | 24 | dead/crash x=4643.3 | **exact** |
| 45 FPS | 768 | 1.000 | 24 | dead/crash x=4643.3 | **exact** |
| 60 FPS | 767 | 0.9987 | 24 | dead/crash x=4643.3 | — |
| 120 FPS | 767 | 1.000 | 24 | dead/crash x=4643.3 | **exact** |
| jitter ±50 % | 767 | 0.9988 | 24 | dead/crash | — |
| один gap 220 мс | 767 | 0.9881 | 24 | dead/crash | — |

`worst |Δx| = 0`, `worst |Δang| = 0` на всех 767 сравнённых тиках.
Разброс `physicsSteps` = 1 — граничный шаг на самом конце 20-секундного окна.

Гейты `__timingTest` (все 10 — `pass`):

1. `simToRealRatio` 1.000 ± 0.005 на 30/45/60/120 → `30:1 45:1 60:0.9987 120:1`
2. `physicsSteps` совпадает ±1 → `768 768 767 767`
3. порядок contact events совпадает → 24 события, идентичная последовательность
4. исход (death/finish) совпадает → `dead/crash`
5. момент ввода расходится ≤ 1 `SIM_DT` → `0 0 0`
6. состояние побитово совпадает на одинаковом тике → `exact` ×3
7. gap: clamp/drop зарегистрирован, ложных контактов нет → `long 1, dropped 0.1367 с, cev 24/24`
8. нет спирали смерти: accumulator после слива < `SIM_DT` → на всех прогонах
9. catch-up за кадр ограничен `TM_MAX_STEPS` → `max steps/frame: 3 2 2 1 2 5`
10. сравнение шло по каждому тику (`sampleEvery=1`) → 767 тиков

**Честная оговорка о гейте №5.** Ввод подаётся по часам `_tmConsumed` — реальным секундам,
фактически превращённым в шаги. Они растут ровно на `SIM_DT/timeScale` за шаг и потому не зависят
от раскладки шагов по кадрам. Значит квантование ввода к sim-тику — **свойство конструкции**,
а не измеренный результат; гейт №5 подтверждает отсутствие ошибки в реализации, но не является
доказательством «ввод одинаков при любом FPS» для **живой** игры. Живой ввод приходит из DOM
в произвольный момент кадра — это закрывает только трейс с телефона.

Что реально измерено и могло провалиться: число шагов на единицу реального времени, состояние
физики на одинаковом тике, число и порядок contact events, исход, поведение аккумулятора.

Дополнительно `[ИЗМ]`:
- **детерминизм**: 3 прогона по 479 шагов — побитово идентичны, contact-порядок совпал;
- **рестарт с чекпоинта**: 3 рестарта дают одинаковое стартовое состояние и одинаковое
  состояние через 300 фикс-шагов;
- **пауза**: 0 физ-шагов на экране паузы; первый кадр после возобновления — 0 шагов (ресинк),
  далее ровно 60 шагов на 60 кадров;
- **экран смерти**: 0 физ-шагов; рестарт даёт `accumulator = 0`;
- **resize на ходу**: без NaN; NaN-сводка по `bike` и по всему отчёту пуста;
- **клавиатура**: пробел = газ, `P` = пауза/возобновление — работают в fixed.

## 9. Негативные контроли

`[ИЗМ]` Все три обязаны обнаружить поломку. Если хоть один «зелёный» — тест не доказательство.

| # | Что ломаем | Ожидание | Получено | Обнаружил |
|---|---|---|---|---|
| NC1 | `legacy` при 30 FPS | ratio ≈ 0.5 | `legacy30 = 0.5017` (300 шагов) против `legacy60 = 1.0017` (601 шаг) | **да** |
| NC2 | копия трейса без одного `touchend` | залипшее действие | `unclosedTouch{id:1, zone:"gas"}` + `stuckAction{down}` + `actionWithoutTouch{down}` | **да** |

а не на выдуманном объекте.

## 10. Что рекордер уже показал (данные для 0B)

`[ИЗМ]` Пробный трейс, снятый синтетическими касаниями через реальные обработчики:

```
raw:      start:1:gas | start:2:leanL | move:2:leanL | end:2:leanL | move:1:none | end:1:none
resolved: touchstart{d1, at:{1:gas}} | touchstart{d1, lx:-1, at:{1:gas,2:leanL}}
        | touchend{d1, lx:0, at:{1:gas}} | touchend{d0, at:{}}
```

Палец №1 стартовал на `gas`, сдвинулся на 90 px вверх (в первом прогоне — прямо на кнопку
`brake`, во втором — в зону `none`), а `resolved` всё это время показывает `at:{1:"gas"}` и
`d:true`.

`[ВЫВОД]` Это дефект §6.9 аудита («`touchmove` не переоценивает попадание в кнопку»),
**впервые зафиксированный в данных, а не в чтении кода**. Старый `inpLog` этого показать не мог
в принципе: он писал только итоговую битовую маску и не знал, где находится палец.
В 0A это только измерено — **исправление относится к 0D**.

## 11. Что намеренно НЕ исправлено в 0A

- **`FnDrive`, тяга, опрокидывающий момент ×2.3 (§6.5)** — это 0B. Power-loop не тронут.
- **`PHX`-калибровка и инвертированная кривая сложности (§6.4)** — 0C.
- **`touchmove` без переоценки кнопки, дискретный наклон ±1, размер кнопок (§6.9, §9)** — 0D.
  0A их только измеряет.
- **Крипто-слой в срезе, экран смерти, PUMP (§6.7)** — вне 0A.
- **Герой 4.7 % высоты, композиция под landscape (§6.2, §6.3)** — 0D / курс B.
  `[НАБЛ]` На скриншоте SE 320×568 блок кнопок вплотную подходит к байку и дороге —
  подтверждает §6.3, но в 0A не трогается.
- **`slowLerp` в legacy** — прежнее поведение сохранено намеренно, legacy это контроль.
- **Мёртвый код** — по решению пользователя только помечен `dormant`, не удаляется.

## 12. Известные ограничения и что осталось недоказанным

1. `[НЕ ДОКАЗАНО]` **Реальный FPS и `simToRealRatio` на устройстве.** В headless-пане rAF
   приостановлен (`renderFrames = 0` за 2.5 с настенного времени), живой цикл здесь не
   измеряется. Это закрывает только трейс с телефона.
2. `[НЕ ДОКАЗАНО]` **Влияние fixed-времени на играбельность.** 0A не трогал тягу; §6.5
   остаётся в силе, вилли на удержанном газе никуда не делся.
3. `[НЕ ДОКАЗАНО]` **Величина рассинхрона «физика / риг»** (§6.10 аудита). Риг по-прежнему
   читает `performance.now()` (или `__rigDt`). В fixed-режиме физика идёт по реальному времени,
   так что расхождение должно уменьшиться, но **измерения нет** — гипотеза не проверялась.
4. `[НАБЛ]` **`__cutSelfCheck` на HEAD даёт 9/12, а не заявленные в доках 12/12** — при
   `__rigDt=1/60`, и в портрете 430×932, и на десктопе 1280×800. Фейлят
   `uphill_hold_1s_30_40deg`, `uphill_no_state_flicker`, `apex_tuck_knees_fold`.
   Это **преждее расхождение**, не регрессия 0A: baseline снят с `HEAD:toys/chartrider.html`
   и совпадает до строчки. Разбираться — отдельно.
5. `[НАБЛ]` **`NO_TILT` зависит от ширины окна**: 89 % при 430×932 и 87.3 % при 1280×800.
   Как якорь регрессии годится только при фиксированном viewport. `GAS_ONLY` стабилен (41.6 %).
6. `[ИЗМ]` **`__rigAssert` после `__cutSelfCheck` даёт 40 ошибок** (`reboundBeforeAnyCompression`,
   `reboundWithoutCompression`) — **и на HEAD ровно столько же**. После `__vsRun` — 0 ошибок,
   тоже как на HEAD. Пред-существующее, не 0A.
7. Реплей квантует ввод к sim-тику по конструкции — см. оговорку в §8.
8. `slowmo` в fixed стал дробным (реальные секунды вместо целых кадров). Все читатели
   проверяют `slowmo>0` / `Math.max(slowmo, N)`, дробность безопасна.
9. `[НАБЛ]` **`window.screen.orientation` в headless-Electron отдаёт `landscape-primary` даже
   при портретном viewport 430×932.** Поле `or` в raw-событиях трейса поэтому недостоверно
   в этой среде. На реальном Safari ожидается корректное значение — но это **предположение,
   не измерение**, проверится первым же трейсом с телефона.
10. `[НЕ ДОКАЗАНО]` **Кнопка ⬇ JSON на iOS.** Скачивание Blob-ссылки проверено только во
    встроенном браузере (файл появился в `~/Downloads`). Поведение мобильного Safari
    не проверялось. Ровно поэтому рядом стоит **⧉ КОПИЯ** с двойным запасом:
    `navigator.clipboard`, а при отказе — текстовое поле с уже выделенным JSON.
