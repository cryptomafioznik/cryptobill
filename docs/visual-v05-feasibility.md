# VISUAL V0.5 — FEASIBILITY REPORT

**Вердикт:** направление технически осуществимо как visual prototype.

**Статус:** `PROTOTYPE / MANUAL_REVIEW_REQUIRED`

**Не является разрешением на production integration.**

## Что доказано прототипом

- Точный боковой профиль можно визуализировать настилом 8–14 px без 3/4-перспективы и без глухой заливки вниз.
- Открытые балки, фермы и редкие опоры сохраняют читаемость города между элементами конструкции.
- Крутые участки допускают адаптивные опоры: их длина вычисляется от локального профиля до общей опорной отметки.
- Gap может быть честным разрывом всех слоёв трассы с видимыми торцами.
- Четыре фоновых плана можно двигать независимо, не меняя физическую геометрию трассы.
- Героя можно нормализовать по реальным alpha-bounds, а не по квадратной ячейке atlas.
- Текущая раскладка четырёх touch-действий помещается в 320×568 без пересечений.

## Реализация lab

`toys/visual-v05.html` — автономная Canvas-лаборатория. Код и стили находятся в `toys/visual-v05/`. Она переиспользует существующие bitmap-слои V0 и рисует дополнительный город, свет, атмосферу и всю конструкцию процедурно. Новых ImageGen-ассетов не потребовалось.

Лаборатория поддерживает:

- статические состояния `flat`, `climb`, `air`, `compression`;
- 10-секундный loop;
- clean export без панели лаборатории;
- structure-debug с collision/deck/support overlays;
- фиксированные review-размеры через query params;
- детерминированный `frame=0…9999` для воспроизводимой записи видео.

Фиксированный экспорт использует backing store 1:1 к CSS px. В интерактивном режиме сохраняется device DPR до 2×.

## Стоимость рендера

На каждом кадре выполняются:

- 3 bitmap draw-прохода фона;
- 2 процедурных прохода зданий;
- 1 ближний процедурный/bitmap-проход;
- построение профиля с дискретизацией 4 CSS px;
- один проход настила, нижнего пояса, диагоналей и редких опор;
- один atlas draw героя и один повтор для чёткого края;
- HUD и четыре touch-кнопки.

На 430 px ширины профиль содержит около 115 точек. Геометрия не требует WebGL, сложной маски или полноэкранных post-effects. Для visual prototype Canvas 2D достаточен; production-бюджет кадров этим отчётом не сертифицирован и должен быть измерен на целевых телефонах.

## Перенос в production hybrid-rig

Возможный перенос масштаба не зависит от atlas:

1. собрать production-позу из всех видимых частей;
2. вычислить union visual bounds после локальных трансформаций;
3. выбрать полезную высоту с учётом safe-area;
4. применить `scale = usefulHeight × 0.15…0.18 / unionHeight`;
5. привязать нижнюю контактную точку колёс к collision line;
6. повторить измерение для крайних поз и проверить отсутствие scale pumping.

В V0.5 используется 17%. Это доказывает композиционный диапазон, но не динамику рига, качество суставов, squash, suspension или pose blending.

## Ограничения и риски

| Риск | Состояние V0.5 | Следующая проверка |
|---|---|---|
| Фермы создают визуальный шум на крутых участках | частично снижено редким шагом | ручное ревью climb/landing |
| Near layer конкурирует с героем | снижена alpha и calm-zone | просмотр видео на телефоне |
| Data-маркеры выглядят как декор, а не финансы | оставлены редкими | сравнение без/с маркерами |
| 8 fps review-video недостаточно для motion polish | достаточно для направления | real-time 60 fps профилирование позже |
| Brake неудобен для большого пальца | геометрически помещается | обязательный touch-тест |
| Atlas скрывает проблемы hybrid-rig | не проверено | отдельный rig prototype |
| Фоновый bitmap может быть слишком мягким на части экранов | проверен на целевых размерах визуально | device QA по контрасту |

## QA, выполненный на прототипе

- `node --check toys/visual-v05/app.js` — пройден.
- Рендеры сняты непосредственно из lab в 430×932, 430×791 и 320×568.
- Видео проверено через `ffprobe`: H.264, 430×932, 8 fps, 10,000 с.
- Контрольные кадры видео проверены на 0, 2,5, 5,0 и 7,5 с; последовательность показывает flat, climb/crest, gap/air и landing/flat.
- Alpha bounds получены из исходного RGBA atlas при пороге `alpha > 8`.
- В чистых кадрах отсутствуют `ЗОНА ПОСАДКИ` и название `HONEST SIDE 2D+`.
- `toys/chartrider.html`, physics, timing, PHX, touch logic и current handoff не изменялись.

## Условия перед любым production-переносом

Production integration возможна только после отдельного решения ревью и как новый этап. До него нужны:

1. ручное утверждение Elevated Technical Chart Track;
2. реальный touch-тест brake/gas и weight-контролов;
3. проверка 60 fps на минимальном целевом устройстве;
4. отдельное доказательство production hybrid-rig;
5. утверждение контраста четырёх планов на физическом экране;
6. подтверждение того, что collision line и торцы gap совпадают с production physics.

Текущий результат сознательно останавливается на visual prototype и не меняет production-код.
